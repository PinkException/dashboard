## Slice 012-02 — parked section and slice goals

**Goal:** The roadmap tab gains a **Parked** section — dashed cards for
DEFERRED slices, each with its "Revisit when …" trigger — and every slice card
gets its one-line goal, so the tab reads like the reference roadmap page without any
snapshot.

**DoR:**
- ✅ 012-01 DONE (tab, cards, order in place).

**Acceptance Criteria:**

1. **Goal line.** The scanner adds `goal` to each slice record: the first
   sentence of the `**Goal:**` paragraph — or, when absent, a
   `**Goal (…):**` paragraph (P3: 4 of 42 deferred slices) — plain text (markdown emphasis and
   links stripped), capped at a fixed length with an ellipsis. Absent →
   no goal line on the card (A1).
2. **Trigger.** The scanner adds `trigger` to each DEFERRED slice: the text of
   its `**Resolution trigger:**` paragraph — the label line plus following
   lines up to a blank line, heading, list item or next bold label (P3: 13 of
   40 triggers wrap) — shown whole up to the cap (not cut to one sentence, so
   "A. Or B." never reads as just "A"). Whenever any text is dropped, by goal
   sentence cut or by cap, the shown text ends with "…". Sentence splitting
   ignores dots in abbreviations, filenames and versions ("e.g.",
   `server.mjs`, `0.6.0`). The cap is set after measuring goal/trigger
   lengths over P3's sample (recorded in the deviation log).
   Absent → the card says nothing about a trigger (A2) — never a guessed one.
3. **Parked section.** Below the spec groups, a "Parked" section lists every
   DEFERRED slice from **every** spec — including finished specs with a
   deferred tail, which stay in the "show N done" fold as specs — as one
   dashed card per slice with a "Parked" chip, the slice ID, name, goal, and
   "Revisit when: <trigger>". The count equals 012-01 AC4's "N parked" (a
   slice count). No spec-level parked card. A spec whose own frontmatter
   status is ABANDONED contributes no parked cards.
4. **Bounded reads.** Goal/trigger extraction reads only the slice files
   `scanSpecs` already opens (no new file walk); a scan of the surveyed
   projects stays within the current `/api/data` timing envelope (measure
   before/after; record numbers in the deviation log).
5. **Escaping.** Goal and trigger text are HTML-escaped (`esc`) — a slice
   containing `<script>` renders as text (fixture test).

### Deviation log (after reconciliation)

The original spec is preserved above. Implementation notes:

1. **Cap = 300 characters (AC2).** Measured uncapped over every slice file in
   the 8 configured projects (anonymized aggregates):

   | Text | n | median | p75 | p90 | max | > 240 | > 300 |
   |---|---|---|---|---|---|---|---|
   | Goal, first sentence | 474 of 477 slices | 210 | 262 | 328 | 561 | 163 | 74 |
   | Trigger, full paragraph | 40 of 42 deferred | 191 | 282 | 491 | 1277 | 13 | 7 |

   3 slices have no goal, 2 deferred slices no trigger (honest absence).
   A 240 cap would cut ~34% of goals (median is already 210); 300 cuts ~16%
   of goals and ~18% of triggers — only the long tail. One constant,
   `TEXT_CAP` (`src/lib.mjs`). The first implementation pass left the
   constant at 240 by mistake (a failed in-place edit); caught by comparing
   the report with the code, fixed before REVIEWED.
2. **Timing (AC4).** `scanAll` with `gh` disabled (the `/api/data` path),
   6 runs each over the configured projects: before ≈ 1.2 s steady
   (1.17–1.25 s, cold first run 2.7 s); after ≈ 1.3 s steady (1.22–1.65 s,
   cold 1.4–2.8 s). ≈ +0.1 s steady (one run reached 1.65 s), within the `/api/data`
   envelope — extraction reuses the slice body
   `scanSpecs` already parses; no new file reads.
3. **Amends 012-01 behaviour (AC3 alignment).** The strip's "N parked" now
   equals `roadmap.parked.length`, so it no longer counts DEFERRED slices of
   specs whose own status is ABANDONED. The 012-01 AC6 render test ("DEFERRED
   slices are not cards") was narrowed to the page before the Parked section
   and retitled as amended by 012-02 AC3.
4. **Contract shape.** `goal` is on every slice record and every slice-backed
   card (`null` when absent); the release placeholder card for an unresolved
   Include token has no `goal` key (render guards with `c.goal ?`). `trigger` is present **only on DEFERRED slice records** (absent,
   not null, elsewhere — commented in `src/scan.mjs`); parked cards carry
   `trigger: null` when absent. Recorded in `docs/architecture.md`.
5. **Choices the ACs left open.** Parked cards are sorted by spec number, then
   the in-spec dependency/slice-number order (the craft review found the
   first pass followed unsorted `readdirSync` order). Parked cards show no
   "Depends on" line. A goal cut after its first sentence drops a trailing
   "." but keeps "?" / "!" before the "…".
6. **Review findings folded in before REVIEWED** (compliance + craft both
   `pass`, no blockers): paragraph stop now requires a label colon, so a
   wrapped line starting with **bold** no longer silently truncates the
   goal; code spans are protected from emphasis stripping (`` `__init__` ``
   keeps its underscores); "?"/"!" ellipsis test; a test asserting
   non-parked cards carry no `trigger`; an `indexOf > -1` guard in the
   render test. Each new test was mutation-checked (feature mutated → red →
   restored). The mutation run also caught a real bug in the first pass:
   the abbreviation regex lacked its trailing `\.`, so "e.g." guarding
   never fired.
7. **Parked, not fixed** (`docs/inbox.md`, 2026-11-17): regex-markdown limits
   (`_underscore_`, reference links, labels in code fences), single-letter
   initials splitting a sentence, `rmParkedCard` duplicating `rmCard`
   markup; also notes the no-"Depends on" choice from deviation 5.
8. **Integration.** Merged `origin/main` (0.7.0 release commits — plugin
   version, CLAUDE.md, lightweight decisions; no overlap) before
   reconciliation; suite green after merge (437/437).
