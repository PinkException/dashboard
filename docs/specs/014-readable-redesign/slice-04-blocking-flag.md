## Slice 014-04 — blocking flag and blocked-spec link

**Goal:** When an owner decision holds up other work, the overview row and
queue card carry a red **Blocking** chip and a stronger tint, and the detail
banner says which spec is held ("Spec 021 can't move until you choose").

**Resolution trigger:** the owner asks for the blocking flag, and a rule for
"blocking" (see Open rule below) has been probed against real compass
blockers and confirmed by the owner. Parked 2026-11-17 (spec 014 D4).

**DoR:**
- ⬜ A written rule for "blocking" (see Open rule below), owner-confirmed.

**Open rule (to settle before READY):** today DECIDE comes from free-text
compass blockers (`src/lib.mjs:801-804`) with no spec id. Candidate rule: a
DECIDE is *blocking* when the blocker text names a spec id (`spec NNN` /
`NNN-NN`) that has a slice in IN_PROGRESS or READY_FOR_IMPLEMENTATION; that
spec id is the "held" spec. Needs a probe against real compass blockers.

**Acceptance Criteria (provisional):**

1. The scanner emits `waitingOn.blocking` (boolean) and `waitingOn.holds`
   (spec id or null), pure + fixture-tested in `src/lib.mjs`; additive.
2. Overview row + queue card: red "Blocking" chip (`#B5372B` on white) after
   the state chip; row tint `#FCEFE9`; wait line "Waiting on you — other work
   is stuck behind it".
3. Detail banner adds "Spec NNN can't move until you choose." when `holds` is
   set.
4. With no blocker naming a spec, nothing changes (no false "Blocking").
