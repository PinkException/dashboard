## Slice 007-02 — README onboarding section

**Goal:** the README walks a brand-new plugin user from install all the way to the
optional automatic snapshot routine — so the feature spec 006 shipped is actually
discoverable, in the right order, with its owner-gated caveat.

**DoR:**
- ✅ Spec 006 (routine installer) is DONE — the `install-routine.mjs check` /
  `install` commands and the scheduled-task step exist to document.

**Acceptance Criteria:**

1. **A first-run walkthrough exists.** The README documents the new-user path as an
   ordered sequence: (a) install the plugin (marketplace add + install); (b) run
   `/dashboard:open`, which creates `~/.claude/my-dashboard/config.json` on first
   use; (c) *optionally* arm the automatic routine. The **open-first ordering** is
   explicit — the config must exist before the routine can run.
2. **The automatic routine is documented.** A section explains: the routine is
   opt-in and owner-gated; `node tools/install-routine.mjs check` reports drift
   read-only; `install --approved-by-owner` (with `--force` to adopt an existing
   unmanaged file) copies the version-controlled routine to the live scheduler; and
   enabling the actual schedule is a **separate** step. It states plainly that the
   routine writes only to the dashboard-owned store, never into any surveyed repo.
3. **Accurate to the shipped behaviour.** Command names, flags, paths
   (`~/.claude/my-dashboard/…`, `~/.claude/scheduled-tasks/…`), and the exit-code /
   manifest facts match slices 006-01/006-02 and ADR-0005 as landed — no invented
   flags or paths.
4. **No private data.** The README names no real surveyed-project folders or the
   owner's personal path list; it uses the placeholder/example shape only, and
   passes `test/no-leaks.test.mjs`.

**Notes / scope.**
